Wake timer

A clock inside rakitsu serve runs cheap checks on a schedule. While nothing is wrong it makes zero model calls. When a check raises an alarm, it injects one normal turn into the same chat session.

The timeline is a simulation of the rules in internal/wake/engine.go (the order of decisions is the same). The recording at the bottom is a real run of the real binary with the same numbers (10 s base, factor 1.5, max 20 s, cap 2). The button "Replay the recorded run" feeds the simulation the same steps and you can compare the two audit logs.

Simplifications: no jitter (the default is 10 percent), and a turn finishes at once, so "a turn is already running" never happens here. One turn is counted as one model call; a real turn can use more (in the recording the one turn used 4 calls and its started task used 1 more). Quiet ticks never touch the model.

The rules in one list

  1. Every tick starts by looking for the kill-switch file. If it is there, the loop stops and the session stays open.
  2. Checks run (file, HTTP). They are read-only and free.
  3. All checks fine: this is a quiet tick. The next wait is multiplied by backoff_factor, up to max_interval_seconds. An audit line is written, no event is emitted, no model call.
  4. Anything not fine: the wait goes back to the base interval. If it is the same alarm as the last escalated one, it is suppressed (single_flight, reason alarm_unchanged) until a quiet tick or a different alarm re-arms it.
  5. If max_turns_per_hour turns already happened in the last hour: suppressed as hourly_cap.
  6. Otherwise one timer-sourced turn is injected into the session (level: L2).

Source: docs/wake-timer.md, internal/wake/engine.go.
