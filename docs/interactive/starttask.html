start_task: only what is on the list

A woken session can start independent task runs, but only configs you listed, with only the parameters you declared. Everything else is refused before a task slot is used.

checker The checker below applies the same gates in the same order as TaskManager.Start in internal/wake/tasks.go. The last section is a real run: the real server accepted summary-note and refused not-on-the-list.

The config being enforced

settings:
  wake:
    max_tasks_per_hour: 2
    max_concurrent_tasks: 1
    allow:
      paths: [./logs, ./out]
      configs:
        - name: bearish-report
          path: tasks/bearish-report.yaml
          task: Write a short report on a bearish flip.
          params:
            trend: { type: enum, enum: [down] }
            file:  { type: path }          # relative, under allow.paths
            count: { type: int, max: 20 }  # 0..max

Same shape as the example in docs/wake-timer.md.

Other rules that are not gates

  • Config snapshot: at session start the sha256 of each listed file is recorded. A change, swap or removal later means task_config_changed.
  • The task prompt is your fixed task text plus a fenced block key=value (sorted). Values are enum members, safe relative paths or bounded integers, so no free text or newline can get in.
  • The task runs independently with the server process environment only. It cannot start tasks, has no user_input and no session messaging.
  • The wake session only sees a status and a summary of at most 300 characters. The full result goes to ~/.rakitsu/wake/<session-id>.tasks/<task-id>.log (mode 0600).
  • Each task has a timeout (task_timeout_seconds, default 300). The stop route, the kill switch and closing the session cancel running tasks unless cancel_on_stop: false.
